# EvidenceCheck — revenue playbook

The objective is lawful revenue generation without buying traffic or fabricating demand. The same product is exposed through several independent channels so a failure in one channel does not stop the others.

## Channel 1 — paid agent/API usage

- `/web-extract` from $0.005
- `/site-audit` $0.01
- `/vendor-preflight` $0.025
- `/analyze` from $0.005
- USDC on Base via x402
- Machine-readable discovery: OpenAPI, LLMs, agent card and x402/Bazaar metadata

Primary metric: paid requests per day and repeat request rate.

## Channel 2 — fixed-scope vendor review

Offer: US$495 starting scope for one vendor, public-site preflight, supplied evidence review, findings/gaps/questions and a human-readable deliverable.

Primary metric: qualified requests and paid reviews.

## Channel 3 — recurring monitoring

Offer a recurring program around vendor portfolio size, cadence and human review. Do not promise continuous monitoring until the required data collection and alerting are implemented.

Primary metric: monthly recurring revenue and vendors monitored.

## Channel 4 — MSP/MSSP partner delivery

Offer service providers a repeatable evidence-first first pass that can be incorporated into client engagements. Partner pricing should be negotiated around volume and branding requirements.

Primary metric: active partners and monthly client/vendor volume.

## Channel 5 — procurement volume plans

Sell prepaid or contracted API volume to procurement/third-party-risk teams that need predictable spend. Keep the API self-serve path available.

Primary metric: contracted request volume.

## Channel 6 — custom integrations

Scope implementation separately from usage. Candidate integrations include procurement systems, GRC workflows, ticketing systems, agent orchestration and internal APIs.

Primary metric: implementation contracts and expansion revenue.

## Channel 7 — funded agent work

The BasedAgents worker scans for funded tasks matching vendor/security/research capabilities, applies a minimum bounty threshold and rejects tasks involving unauthorized access, credentials, exploitation, malware or other unsafe work. It must never claim revenue until a marketplace receipt confirms delivery/payment.

Primary metric: claimed funded tasks, delivered tasks and confirmed payouts.

## Distribution

1. x402/Bazaar discovery for machine buyers.
2. OpenAPI and agent metadata for developers.
3. Public buyer/demo pages for human buyers.
4. GitHub repository and documentation for technical discovery.
5. Partner page for MSP/MSSP channels.
6. Search-indexable landing pages and sitemap.
7. Direct, permission-based outreach only; no bulk spam, fake identities or misleading claims.

## Revenue integrity

Never count internal transfers, self-funded tests, simulated payments or agent-to-agent payments between wallets controlled by the same owner as revenue. Only count an external payment or a confirmed marketplace payout.
