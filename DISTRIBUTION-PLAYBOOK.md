# Distribution playbook

## Human buyers

- Buyer landing: `/buy.html`
- Commercial review: `/commercial` on the API service
- Growth matrix: `/growth.html`
- Live demo: `/demo` on the API service
- Sample report: `/sample-report`

The message should stay outcome-focused: reduce repetitive vendor first-pass research, expose evidence gaps, and produce concrete follow-up questions.

## Technical buyers

- OpenAPI: `/openapi.json`
- Agent instructions: `/skill.md`
- LLM discovery: `/llms.txt`
- Agent card: `/.well-known/agent-card.json`
- x402 discovery: `/.well-known/x402`
- Bazaar discovery extension on paid routes

Keep schemas explicit and descriptions concise so machine discovery can classify the service correctly.

## Permission-based outreach

Target roles:
- Procurement operations
- Third-party risk
- Security governance
- Vendor risk management
- GRC leaders
- MSP/MSSP owners
- AI-agent platform builders

Do not send bulk unsolicited messages. Use opt-in communities, relevant directories, product listings, direct introductions and one-to-one outreach where contact is appropriate.

## Proof assets

Use the free/demo path as the low-friction proof. Use the sample report to demonstrate the deliverable. Use the $495 fixed-scope review only after the buyer understands scope and limitations.

## Conversion ladder

1. Discover → 2. Free/demo check → 3. $0.025 machine preflight → 4. $495 fixed-scope review → 5. recurring monitoring / partner / integration contract.

Do not represent the ladder as guaranteed conversion; measure each step.
